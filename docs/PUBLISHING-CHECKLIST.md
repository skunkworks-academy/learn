# Publishing checklist

## Course definition

- [ ] Course code, title, level, version and status are correct.
- [ ] Audience, prerequisites and estimated duration are realistic.
- [ ] Outcomes are measurable and mapped to modules and assessment.
- [ ] Delivery modes, lab requirements and credential rules are defined.

## Learner access

- [ ] Registration URL opens the central Academy identity flow.
- [ ] Enrolment URL identifies the correct course or cohort.
- [ ] Login URL returns enrolled learners to the protected platform.
- [ ] Payment, approval, prerequisite and voucher rules are documented.
- [ ] No local password or learner-data collection exists on the static site.

## Public-content boundary

- [ ] No protected lesson bodies are committed publicly.
- [ ] No assessment banks, answer keys or grading secrets are public.
- [ ] No learner records, credentials, tokens or lab secrets are present.
- [ ] Public samples are approved and clearly identified.

## Quality and compliance

- [ ] Subject-matter review is complete.
- [ ] Instructional-design review is complete.
- [ ] Accessibility and keyboard testing are complete.
- [ ] Mobile layouts have been tested.
- [ ] Images include appropriate alternative text.
- [ ] Videos include captions or transcripts.
- [ ] Source licences and attribution are recorded.
- [ ] Privacy and consent wording is approved where relevant.

## Web readiness

- [ ] `course.config.json` passes schema and repository validation.
- [ ] Canonical global navigation loads and no duplicate top menu exists.
- [ ] Canonical domain, sitemap and robots file match.
- [ ] Social metadata and structured data are correct.
- [ ] Internal links and the production Docusaurus build pass.
- [ ] GitHub Pages is configured to deploy with GitHub Actions.
- [ ] Custom DNS and HTTPS are valid.

## Release

- [ ] Version and changelog are updated.
- [ ] Course status is set to `published`.
- [ ] Enrolment and learner support teams are briefed.
- [ ] Rollback and retirement paths are documented.
