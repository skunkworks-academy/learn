# Contributing

## Branch and pull-request workflow

1. Create a focused branch from `main`.
2. Update `course.config.json` before changing course-specific presentation.
3. Keep public and protected learning content separated.
4. Run `npm install` after dependency changes and commit the generated lockfile.
5. Run `npm run validate` before opening a pull request.
6. Include screenshots for user-interface changes.
7. Describe accessibility, mobile and learner-access impacts in the pull request.

## Content quality

Learning content must be accurate, outcome-aligned, original or properly licensed, accessible, inclusive and written for the stated learner level. Claims, technical commands and vendor-specific procedures must be verified against authoritative documentation.

## Required review areas

- instructional design
- subject-matter accuracy
- assessment alignment
- accessibility and responsive behaviour
- security and privacy
- intellectual property and attribution
- registration and enrolment flow
